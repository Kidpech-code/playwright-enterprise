Testing Companion

Privacy Policy · Last updated: June 4, 2026

Testing Companion is a Chrome Extension for controlling local Playwright Enterprise manual testing sessions. This policy explains what data the extension accesses, how it is used, and where evidence artifacts are stored.

Summary

Testing Companion is designed for local manual testing workflows. The extension connects to a local Playwright Agent running on the tester's machine and sends user-triggered control commands: start, pause, screenshot, checkpoint, bug marker, cursor toggle, and stop.

Testing Companion does not sell data, does not use data for advertising, and does not transmit testing artifacts to third-party services.

Data the Extension May Access

The local Playwright Agent (not the extension itself) may generate the following artifacts when a tester actively triggers evidence capture:

  • Screenshots of the page under test
  • DOM snapshots of the page under test
  • Console logs and network failure summaries
  • Playwright trace files
  • Video recordings of the Playwright-managed browser viewport
  • Tester-entered notes, checkpoints, categories, and severity labels
  • Local report metadata: target URL, viewport size, timestamps, artifact paths

The Chrome Extension itself stores only lightweight local preferences:

  • The configured local WebSocket Agent URL (e.g. ws://127.0.0.1:3737)
  • Cursor visibility preference

How Data Is Used

Data is used only to support manual testing evidence capture and local report generation. The extension sends commands to the local Playwright Agent over WebSocket. The Agent performs screenshots, DOM snapshot capture, video recording, trace capture, and report generation.

Where Data Is Stored

Generated testing artifacts are stored locally in the configured project workspace:

test-artifacts/session_<timestamp>/
  summary.html
  manual-session.json
  log.json
  screenshot.png
  trace.zip
  video/video.webm
  screenshots/
  snapshots/
  session_<timestamp>.zip

The extension does not upload these files. Testers or teams decide if and how to share generated ZIP bundles or reports.

Data Sharing

Testing Companion does not share data with third parties. If a tester manually sends a generated report, ZIP bundle, screenshot, DOM snapshot, trace, video, or log to another person or system, that sharing is controlled by the tester or their organization.

Remote Code

Testing Companion does not execute remote code. All extension files are packaged with the extension at install time.

Network Communication

Testing Companion communicates with the local Playwright Agent over WebSocket. The default URL is ws://127.0.0.1:3737. The extension content security policy allows WebSocket connections to localhost only: 

ws://127.0.0.1:* ws://localhost:*

Permissions

  • activeTab — coordinate cursor visibility with the active page during a manual testing session
  • tabs — identify the active tab so cursor overlay updates reach the correct page
  • storage — remember local preferences: WebSocket Agent URL and cursor visibility state
  • <all_urls> host access — the content script must run on any URL the tester opens for manual testing (local, staging, QA, or production-like environments)

User Control

Users control when testing sessions start and stop. Users also control when screenshots, checkpoints, notes, and bug markers are captured through the extension popup. Generated artifacts can be deleted at any time by removing the local test-artifacts/ session folders.
